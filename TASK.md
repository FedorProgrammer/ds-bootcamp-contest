# Условия задачи

## Контекст
Дана выборка на основе известных источников трафика.
**Положительный класс:** трафик, отнесенный к боту.
**Отрицательный класс:** трафик, отнесенный к человеческому.

## Задача
> По событиям внутри суточного окна построить модель, которая присваивает каждой `cookie_id` оценку от $0$ до $1$: чем выше значение, тем вероятнее принадлежность к положительному классу.

## Данные

### Файлы
- `data/train.csv` -- обучающая выборка с `target`;
- `data/test.csv` -- обучающая выборка без `target`;
- `data/events.csv.gz` -- события для построения признаков;
- `sample_submission.csv` -- пример файла для отправки решения.

> Одна строчка в `train.csv` и `test.csv` соответствует одной `cookie_id` с заданным суточным окном наблюдения.
> `cookie_id` нужно сохранить в файле с ответом.

#### train.csv и test.csv
**Содержание:** метаданные куки и границы окна наблюдения:
- `cookie_id` -- id куки;
- `cookie_created_at` -- время первого появления куки (мб раньше начала окна наблюдения);
- `window_start_ts` -- начало окна наблюдения;
- `window_end_ts` -- окончание окна наблюдения;
- `target` -- целевая переменная.

> Готовых *поведенчиских* фич нет(((

#### events.csv.gz
**Содержание:** история событий для куки из трейна + теста:
- `cookie_id` -- id куки;
- `event_ts` -- время события;
- `eid`, `event_name` -- код и название типа события;
- `platform` -- платформа;
- `user_agent` -- строка User-Agent;
- `item_id`, `item_category`, `item_location`, `seller_type` -- id объявления, его категория, локация и тип продавца;
- `search_query`, `search_page` -- поисковый запрос и номер страницы выдачи;
- `pointer_x`, `pointer_y` -- координаты курсора в момент события.

> События включают:
> - просмотры выдачи и объявлений,
> - листание фотографий,
> - переходы на страницу продавца,
> - контактные действия,
> - добавление в избранное,
> - вход в аккаунт и показ капчи.
> Некоторые поля заполнены только для определённых типов событий или платформ.

#### Target
- $\textbf{target} = 1$ -- кука бота.
- $\textbf{target} = 0$ -- кука человека.

> Для каждой `cookie_id` нужно предстказать `score` от $0$ до $1$: чем выше значение, тем вероятнее, что кука приндалежит боту.

> Признаки должны быть доступны на момент окончания окна наблюдения.

## Формат решения
`submission.csv` должен содержать две колонки:
- `cookie_id` -- id куки из `test.csv`;
- `score` -- число от $0$ до $1$, чем выше, тем вероятнее, что кука принадлежит боту.

> Для каждой `cookie_id` из `test.csv` должна быть ровно одна строка. Пропуски, дубликаты и дополнительные куки не допускаются.

### Метрика
> Основная метрика -- **Precision при Recall $\ge$ 70%** на скрытой тестовой выборке.
> Она рассчитывается по кукам, а не по отдельным событиям.

$$
P@R_{\ge 0.7} = \max_{t: Recall(t) \ge 0.7} Precision(t)
$$

> Одинаковые `score` обрабатываются одной группой: при выбранном пороге отмечаются либо все куки с таким значением, либо ни одна.
